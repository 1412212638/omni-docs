# 服务等级协议（SLA）

生效日期：2026 年 8 月 28 日

本服务等级协议（Service Level Agreement，简称“SLA”）说明 OmniRouters 面向符合适用条件的客户提供的 API 网关和模型路由服务的可用性目标、统计口径、免责范围及服务补偿规则。本 SLA 是《[用户协议](/zh/legal/terms)》和《[计费与退款说明](/zh/legal/billing-refund)》的补充文件。

## 1. 适用范围

1. 本 SLA 仅适用于 OmniRouters 控制的 API 接入、鉴权、请求路由及平台侧基础设施。除非产品页面、订单或双方书面协议另有明确约定，本 SLA 不适用于免费试用、赠送额度、测试环境、个人非商业使用或已被暂停、限制、封禁的账户。
2. 本 SLA 不对上游模型供应商的可用性、模型输出质量、内容审核结果、生成耗时、网络传输质量或第三方服务作单独承诺。上游模型不可用时，OmniRouters 可能根据路由策略返回错误、切换供应商或提供其他可用模型，但不保证一定能够切换成功。
3. “故障对象”按具体 API 服务或约定的服务项计算；不同模型、路由或服务项可根据订单及技术记录分别核算。

## 2. 定义与计算口径

### 2.1 服务周期

一个服务周期为一个自然月。服务周期不足一个自然月的，按实际生效天数计算；若订单或书面协议另有约定，以该约定为准。

### 2.2 服务不可用

“服务不可用”是指在 OmniRouters 控制范围内，平台持续五分钟或更长时间无法接收并处理符合要求的有效 API 请求，或持续返回由平台内部故障导致的 HTTP 5xx 错误。短暂、间歇性或不足五分钟的异常不计入服务不可用时间，但我们会根据监控和日志尽力识别同一事件的连续影响。

### 2.3 有效请求

有效请求是指：账户已开通相关服务、余额或额度充足、鉴权信息有效、请求符合产品文档及适用模型协议、未触发内容安全或风控限制，且请求来自正常运行的客户应用。鉴权失败、欠费、参数错误、超出配额、违反政策、恶意或异常流量，以及因客户或第三方原因未能正常到达平台的请求，不计为有效请求。

### 2.4 服务可用性计算

服务可用性 = （服务周期总分钟数 - 服务不可用分钟数）/ 服务周期总分钟数 × 100%

同一时间段内多个故障对象同时不可用的，按故障对象分别核算，但不对同一客户、同一时间段重复计算同一项平台影响。

## 3. 可用性目标

在适用本 SLA 的前提下，OmniRouters 对 API 网关及平台侧请求处理服务承诺每个服务周期的服务可用性不低于 **99.00%**。该指标是服务可用性目标，不代表模型输出一定成功、符合预期或不存在延迟。

## 4. 免责范围

下列情形导致的不可用、请求失败或性能下降不计入服务不可用时间：

1. 计划内维护、升级、迁移、架构变更或紧急安全维护；
2. 不可抗力、自然灾害、战争、骚乱、公共网络故障、政府或监管措施；
3. 上游模型供应商、云服务商、支付机构、网络运营商或其他第三方服务故障；
4. 客户的应用、网络、设备、DNS、代理、配置、凭证、请求格式或集成代码导致的故障；
5. 账户欠费、配额用尽、鉴权失败、违反法律或平台政策、触发安全风控或服务被依法限制、暂停或终止；
6. 攻击、滥用、异常流量、爬取、撞库、DDoS 或其他需要采取保护措施的行为；
7. 模型生成内容被安全策略拒绝、模型本身限流、模型上下文或输入输出限制；
8. 未按文档、订单或双方约定的技术要求使用服务；
9. 未持续达到五分钟的短暂或间歇性异常，以及无法通过合理日志和监控确认的影响。

## 5. 监控、故障处理与证明材料

OmniRouters 以平台监控、网关日志、请求记录和故障工单作为主要核算依据。客户应在发现问题后尽快通过 `support@omnirouters.com` 联系我们，并提供账户标识、请求 ID、发生时间和时区、请求路由、错误信息及脱敏日志。客户不得提供 API Key 完整值或敏感内容。

我们会根据事件影响采取告警、流量调整、故障切换、限制风险流量、修复或其他合理措施。故障处理时间取决于故障原因、影响范围及第三方协作情况；本 SLA 不构成固定的恢复时间承诺。

## 6. 服务补偿

1. 若客户认为服务可用性低于本 SLA 目标，可在相关服务周期结束后 30 日内提交服务补偿申请。申请应列明服务周期、故障对象、受影响时间、请求 ID 或工单号及必要证明。
2. 我们核实并确认平台侧责任后，可根据实际未达标程度向符合条件的付费账户提供服务抵扣额度或其他合理补偿。补偿金额原则上不超过发生故障的服务周期内客户为相关服务实际支付的费用；免费额度、已退款金额、赠送额度和因客户或第三方原因产生的损失不计入补偿基数。
3. 补偿申请不影响我们依据《用户协议》采取安全、合规、风控或账户处置措施的权利。未经核实的监控截图、单个请求失败或上游模型异常，不当然构成 SLA 违约。
4. 除适用法律另有强制规定或双方书面协议另有约定外，服务补偿是客户因未达到本 SLA 可获得的唯一救济。

## 7. 政策更新

我们可根据产品架构、上游服务、运维能力和业务安排更新本 SLA。更新版本将在网站或文档中发布，并自标注的生效日期起适用；已经发生的服务事件按事件发生时适用的版本处理，法律或书面协议另有要求的除外。
